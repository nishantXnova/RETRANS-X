Why Stream Wins at Ultra-Long Context:
The Arithmetic is Non-Negotiable

A deep, honest analysis of Stream's O(n) complexity — compute, memory, and the architecture that makes it possible

1. The Core Truth

Stream is a continuous byte-level state space language model with no attention, no tokenizer, and no positional encoding. Its entire sequence processing is a linear recurrence — a scan — over raw bytes. That single design decision converts the Transformer's O(T²) attention into O(T), and in doing so hands Stream a regime that no Transformer can enter: ultra-long context on commodity hardware.

The claim is arithmetic, not aspiration. At T = 1M, attention would need ~10¹² score pairs per layer. Stream's scan needs a linear pass. That gap is a factor of one million per layer — and no GPU, no kernel, and no batching trick can close a complexity-class gap.

2. The Complexity Wall: O(n) vs O(n²)

2.1 Where the n² comes from

Attention computes, for every token, a score against every other token in the sequence:

compute: Q·Kᵀ + softmax + ·V = O(T² · d) FLOPs per layer memory: T×T score matrix = O(T²) per layer (naïve)

At T = 1M and d = 64:

T² = (10&sup6;)² = 10¹² pairs FLOPs per layer ≈ T² · d = 6.4×10¹³

2.2 The corrected arithmetic (honest numbers)

Getting the absolute seconds right

A T4 does ~65 TFLOPS fp16. So a single idealized attention layer at T=1M costs:

6.4×10¹³ FLOP / 6.5×10¹³ FLOP/s ≈ ~1 second of peak-throughput compute

Not ~1000 seconds — an earlier draft mis-divided by 10³. Real wall time is worse than 1s (memory movement, kernel efficiency, projections), but the honest headline is ~1s of idealized compute per attention layer, and ~30s for 30 layers. The claim does not depend on that absolute constant.

Here is why the argument survives the correction. The relative multiplier is the whole game:

attention per layer / scan per layer = O(T²) / O(T) = T

Honesty box — what this does and doesn't say
  • Corrected: absolute idealized compute per attention layer at T=1M is ~1s, not ~1000s. Real performance is worse than peak, but not by thousands of seconds from the FLOP count alone.
  • Still true: the O(T²) vs O(T) ratio = T = 10&sup6; at T=1M. The scaling gap is complexity-class, not constant-factor.
  • Caveat: for short sequences (T < ~9k), attention's constants are better and it wins on wall-clock. The crossover is measured, not assumed — see §5.

3.1 The two memory costs of attention

FlashAttention caveat kept: modern attention no longer materializes the T×T matrix, so its working memory is ~O(T). But its compute remains O(T²), and during generation the KV cache grows linearly with context — at T=131K with d=4096 and L=36, that is tens of gigabytes before any compute happens.

3.2 Stream: no KV cache at all

Stream's scan compresses the entire past into a fixed-size hidden state per layer. There is nothing to store and re-read per token:

state: O(d_state) per layer, independent of T cache: none → persistent memory is zero for any context length

4. Architecture: Why the Scan Replaces Attention

4.1 The conceptual reason linear works

Attention is brute-force explicit routing: every token reads every token, with full precision. That is maximally expressive but massively redundant, because long-range signal can almost always be summarized rather than looked up pairwise. The scan maintains a fixed-size state that compresses the entire past:

h_t = h_{t-1} · exp(Δt·A) + Δt·B_t·x_t y_t = C_t · h_t + D · x_t

Information propagates state→state at each timestep, so the cost of remembering 100K tokens is identical to remembering 10. Position is encoded structurally by the scan itself — no positional encoding exists anywhere in the model.

Local structure
Depthwise Conv1D
kernel size 4, SiLU — cheap O(T·k) capture of byte-level n-gram patterns
Global structure
SSM Scan
O(T) recurrence — compresses all history into a fixed-size state

4.2 SSMScanFn — the O(T) backward pass

The naïve sequential Python loop builds an O(T²) autograd graph. SSMScanFn (model.py:27) is a custom torch.autograd.Function that runs a forward scan O(T) and a reverse scan O(T) for the backward:

Forward: h_0 = 0 h_t = h_{t-1} · a_t + b_t Backward: dL/dh_T = 0 dL/dh_t = grad_output_t + dL/dh_{t+1} · a_{t+1} dL/da_t = dL/dh_t · h_{t-1} dL/db_t = dL/dh_t

Result: 10× faster backward than JIT autograd, bit-exact gradients, zero autograd graph overhead. This is the implementation later replaced by the Triton kernel (§5).

4.3 Multi-byte head: 4× signal for free

From each position, Stream predicts the next 4 bytes simultaneously via a linear head:

L = (1/4) · Σₛ CE(logits_t,k, b_{t+k})

This yields 4× training signal per position and 4× faster autoregressive decoding — more useful work per unit of sequence processed, which compounds the efficiency story without any extra cost.

4.4 Token-free, position-free

Vocabulary = 256 bytes. No BPE, no WordPiece, no positional band-aid. The absence of tokenization means Stream never pays the lossy byte→token compression tax, and its O(n) cost is in bytes — the most fundamental unit of text.

5.3 Chunked two-level scan (B·H ≤ 128 regime)

A chunk-local scan + inter-chunk carry + parallel broadcast correction fixes the occupancy problem at low batch×heads. The shipped auto-dispatch rule — chunked when B·H ≤ 128, fused otherwise — is backed entirely by measured data:

B·H=128: chunked wins 1.15–1.24× over fused at every T from 4096 to 65536. B·H=192: loses (0.96–0.97×). Sequence length is not a predictor; B·H is.

6. The Honest Tradeoff

Transformers won for a real reason: dense attention has no information bottleneck — any token can route to any token with full precision. Stream's scan is lossy compression: a fixed-size state has finite capacity, so long-range content recall ("the name from 1,000 bytes ago") is weaker than attention's explicit lookup. That is the genuine weakness.

So the claim "that regime is yours by arithmetic" is exactly right about efficiency. The win is guaranteed by complexity theory, not cleverness. The open research question is whether the compressed state carries enough signal — and the empirical answer so far is that the crossover happens around T≈9k, after which Stream's advantage is structural and compounding.

7. Summary

  1. Complexity class: O(n) scan vs O(n²) attention — a factor of T per layer. At T=1M that is a million×, unreachable by any hardware.
  2. Corrected arithmetic: ~1s idealized per attention layer at T=1M on a T4, not 1000s — but the ratio argument is independent of the absolute constant.
  3. Memory: no KV cache, no score matrix, perfect O(n) measured (<3% error at T=65,536). T=131,072 fits in 15 GB.
  4. Architecture: state-space recurrence compresses history into a fixed-size state; O(T) custom backward; multi-byte head gives 4× signal and 4× faster decode.
  5. Measured: crossover at T≈9k on a real T4; flat ~228K tok/s throughput at every length; 5× end-to-end kernel speedup.
  6. Tradeoff: state-bound recall is the real cost — but at ultra-long context, arithmetic makes the regime Stream's.
